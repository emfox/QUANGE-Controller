# 接入米家：同类设备调查与属性映射

调查时间 2026-11-08。目的是回答一个问题：这台设备要改成米家协议，市面上有没有可以直接参照、甚至直接借用的东西。

结论先说：**有，而且不止一层。**

- 业务上，它等价于市面上的「蓝牙时控开关」——BLE + 单路负载 + 定时 + 小程序控制，是成熟公版方案；
- 品类上，米家**已经有 `sterilizer`（消毒器）这个正式设备类型**，属性集和我们的内部状态一一对应，不用自己发明 model；
- 硬件上，米家蓝牙 Mesh 通断器里的模组（MHCB07P / MHCB12S）自带「点动延时」，一颗二十块钱的通断器就能顶掉整块控制板的全部功能面。

---

## 1. 我们这台设备的功能面

从协议和固件里已经坐实的：

| 能力 | 出处 |
| --- | --- |
| 单路消杀负载开关 | 命令 `04` |
| 4 槽本地定时（时:分 + 分钟数），断电保持 | 命令 `07`/`08`，flash `0x41000` |
| 档位时长表 + 固定 180 秒档 | `0x6538`，`+0x60` 档位索引、`+0x50` 起秒数表、`+0x35 != 0` 走 180 秒 |
| 已进行 / 总长秒数 | `+0x3C`（本疗程）/ `+0x48`（开机以来） |
| 结束原因：完成 / 中止 | `0x64D0` 收尾，`fault` 语义 |
| 200 条日志（栈式消费） | flash `0x40000`，命令 `05`/`06` |
| 电量 | 命令 `03`，RAM `0x8435A0` |
| 序列号 / MAC / 版本 | 命令 `09`/`A2`/`A3`/`A5`/`A4` |

## 2. 第一类：同构产品 —— 蓝牙时控开关

淘宝/1688 上的「宽电压蓝牙时控开关」是这个形态的公版：

- 12–260 V 交直流通用，均值电流 6 A；
- 蓝牙直连、**微信小程序**控制（不是 App、不是网关）；
- 30 组定时，时控范围 1 s–168 h，断电靠内部时钟芯片记忆；
- 手动开关 + 定时开关。

和我们的设备对比，**差异只有三处**：我们只有 4 槽定时（它 30 组）、我们多 200 条日志、我们带电池电量。控制方式（小程序 + BLE 私有帧）完全同源。

⟹ 这条证明了「小程序 + BLE 私有协议 + 定时 + 单路负载」是一套成熟方案，我们这台不是孤例，是这套方案的一个定制外壳。

## 3. 第二类：米家同类目 —— `sterilizer`（消毒器）

米家有正式的设备类型 `urn:miot-spec-v2:device:sterilizer:0000A04F`，线上至少有五个型号：

| 型号 | 产品 | 属性集 |
| --- | --- | --- |
| `uvfive.steriliser.suger` | FIVE 杀菌架（简版） | `fault` `mode`(15/30/60 分钟) `on` `status`(Idle/Busy) `target-time` `working-time` `left-time` + `alarm` `physical-controls-locked` `door-state` |
| `uvfive.steriliser.maine` | FIVE 智能刀筷杀菌架 | `fault`(正常/完成/中止) `mode`(普通/快速/最爱) `on` `status`(空闲/风/热/热风/光/…) `target-time` 15–90 步长 5 `working-time` `left-time` |
| `xiaomi.steriliser.uvs01` | 米家智能消毒机 | 11 属性，多出 `reservation-complete-time` `reservation-left-time` `target-temperature` `door-state`，`target-time` 0–4320 |
| `viomi.steriliser.v1` | 云米消毒柜 | 最简：`mode` `status` `left-time` |
| `iot.steriliser.gc01t` | — | — |

**`uvfive.steriliser.suger` 和我们几乎是一个东西**：档位就是时长（15/30/60 分钟），只有一个 Busy 状态，只有剩余时间，没有风/热/光这些多执行器语义。我们那个「180 秒固定档」正好落在 `mode` 上。

这条的意义很大：**米家侧不需要新建品类、不需要自定义 model**，只要按 `sterilizer` 上报，米家 App 就能生成正确的控制卡片（开关 + 档位 + 倒计时），小爱也能正确理解「打开消毒器」。

## 4. 第三类：可当载体的米家硬件

| 模组 | 芯片 | 说明 |
| --- | --- | --- |
| **MHCB07P** | Realtek RTL8762CGL | 米家蓝牙 Mesh 通断器用的就是它；官方报价 5.99 元，**不对个人销售**，数据手册也保密 |
| **MHCB12S** | — | 支持米家蓝牙 Mesh 2.0 |

模组背面那块 8 pin 扩展板丝印是 `GND / 3V3 / W / Y / R / G / B / AC`，`W` 是单路输出（高电平 3.3 V），通断器只用 `W` 和 `AC`。

通断器出厂固件自带的功能（米家 App 里能设）：

- 开关、定时、倒计时、上电默认状态；
- **点动延时 1–7199 秒**（`click-one-timeout`），到点自动断开；
- 灵动（掉电触发翻转）、指示灯模式、继电器状态回读。

⟹ 「点动 180 秒」就是我们的固定档。**一颗二十元的米家通断器，功能面已经覆盖了这台设备除了日志之外的全部能力。**

另外，米家蓝牙 Mesh 的定时和倒计时是**网关/云端调度**的，不依赖设备本地定时表。所以迁移到米家之后，固件里那套 4 槽定时表 + 软定时器 + 日志队列可以整个丢掉——**功能不减，代码变少**。

## 5. 属性映射：15 条私有命令 → sterilizer

| 我们的命令 | 现在的行为 | 米家对应 |
| --- | --- | --- |
| `04` | 立即开 / 关 + 设时长 | `on`(bool) + `target-time` |
| `02` | 状态查询 + 对时 | `status` + `working-time` + `left-time` |
| 档位（`+0x60`） | 档位时长表 | `mode` |
| `0x64D0` 收尾 | 完成 / 中止 | `fault` = 1 完成 / 2 中止 |
| `03` | 电量百分比 | 标准 `battery-level` service |
| `07` / `08` | 4 槽本地定时表 | **不需要**——米家由网关调度 |
| `05` / `06` | 200 条日志（栈式） | 无对应；可保留为私有 service，或丢弃 |
| `09` / `A2` / `A3` / `A5` / `A4` | 序列号 / MAC / 版本 | 由米家认证与 OTA 流程接管 |
| `A0` | 恢复出厂 | 米家 App 的「删除设备 / 重置」 |

一句话：**业务语义是超集，能对上；工程实现是另一套栈，对不上。**

## 6. 三条落地路线

| 路线 | 做法 | 固件改动 | 保留的功能 | 代价 / 风险 |
| --- | --- | --- | --- | --- |
| **1. 硬件桥接** | 原板一行不动，外挂一颗米家通断器，用它的 `W` 输出驱动消杀回路（或反过来，米家模块做 BLE 中心去连原机） | **0 行** | 米家只有开/关 + 点动 | 需要动一次硬件接线；两套电源；原机的小程序仍可用 |
| **2. 换控制板** | 拆掉原 MCU，用米家通断器模组直驱负载 | **0 行** | 米家全功能，但丢了日志与本地定时 | 不可逆（原板要拆）；需要模组来源 |
| **3. 自写 Mi Mesh 固件** | TLSR8258 上跑小米 mesh SDK，实现 `sterilizer` model | **整套业务层重写** | 全部可控，能上报 `mode`/`left-time` | 需要 PID + 认证库；个人开发者通道目前「内测名额已满」；认证库要企业资质 |

三条路的准入门槛差别很大，但**都不需要伪造别人的 PID**：路线 1 和 2 用的是已经通过认证的正规模组，路线 3 走的是官方注册。

## 7. 建议

先做路线 1 的样机验证：它零固件改动、可回退、能立刻验证「米家能不能正确显示和控制这台设备」。验证通过后，再决定要不要为了 `left-time` 倒计时和档位显示去走路线 3。

路线 2 只在「原板已经坏了」或者「确定不要小程序了」的情况下才值得——它把一个可逆的改造变成不可逆的。

## 8. 附：L1 广播补丁的定位

广播层曾经打算用静态补丁做（把 scan response 尾部那个 `07 FF AA AA AA AA AA AA` 换成 MiBeacon 帧），**这条路已经证明不成立**：那 6 个 `AA` 是留给 MAC 的占位，每次广播前都会被真 MAC 覆盖，而且元素只留了 8 字节、装不下 MiBeacon 的强制字段。

⟹ 广播必须是**代码生成**。详见[路线 3 分析](mi-home-route3.zh-CN.md) §3。现在仓库里留存的是 `tools/mibeacon.py`，它是这一层的编解码参考实现（含自检），可以用来校验任何 MiBeacon 帧的合法性。
